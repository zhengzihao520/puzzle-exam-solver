## 结论（决定后续实现）

1. **棋盘检测不能只靠“平坦区”**：居中开局时块铺在棋盘上，棋盘内部不再平坦。
   → 需要补充“棋盘边框检测”作为兜底：棋盘四周有一条比页面更亮的描边矩形（两张图里都能看到），
   用 Canny + 近似矩形拟合可以定位，再用参考面板高度对齐（参考面板与棋盘同高）。
2. **拼块无法用连通域/轮廓一次分出 30 块**：
   - 普通模式：块在托盘里首尾相接（凸台互相咬），CC 会把几十块并成一团；
   - 重叠模式：块成堆叠，下层被遮；
   - 居中模式：块铺在棋盘上，且互相轻微重叠。
   → 改为**探测式拾取（probe-and-place）**：在托盘里取候选抓取点（优先按格点推算，其次在占据区内均匀取样），
   对每个点做一次“轻拖探测”判断该点是否真的抓到块；抓到就裁剪分类，类别匹配空格的直接拖过去，
   不匹配就原位放回。每次放置后重新截屏，因为上层块移走会露出下层。
3. **进度校验用像素而不是 OCR**：进度 N/25 旁边不用识字——每个格子“是否已填”可以直接由
   “该格像素与棋盘底色差异”判定，这也正好给出 hasAnchor 需要的“已填邻居”集合。
