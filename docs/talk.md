# 讲代码：8–10 分钟版

> 一句话：**用 OpenCV 读屏幕、用 YOLO 认类别、用真实鼠标拖拽，把 5×5 拼图拼完。**
> Part 1（照片）25 步拼完 25 格；Part 3（照片+纯白混合）25 步、0 次拒绝。
> 全程不读页面内部数据（不碰 `window.__dev`、不碰 DOM），只看屏幕、只动鼠标。

---

## 1. 数据流（先给全景，别一上来讲细节）

```
截图(mss/PIL)                       vision.layout
   │                                   │
   ├─ 棋盘 (433,453,560,425)  → 5×5 格，每格 112×85
   ├─ 参考面板 (1435,517,451,339) → 25 格小图
   └─ 托盘：6 行×3 列×2 带 = 36 槽（步长 129.92 / 98.6）
                │
                ├─ identify.py   面板每格：纯白？→ blank；否则 YOLO11s-cls + 自训分类器投票
                ├─ stateless.Pieces.inventory   托盘每块：类别 + 48×36 指纹模板
                ├─ panel_match.py  30 块 × 25 格的图像相似度矩阵 → **最优一对一指派**
                └─ white_edges.py  白格：孔的四边剖面 → 白块的四边剖面 → 形状配对
                                │
                          stateless.main 的行动循环
                     每步：重截图 → 定位块 → 拖到格心 → 按 3 次问引擎“锁了吗”
                                   ├─ 锁上 → 记一格
                                   └─ 没锁 → 拖回它原来的槽位（盘中不留块）
```

关键点：**每一动之前都重新截图**（`Snap(mouse.shot())`），不靠记忆里的坐标。这是“无状态”的意思，
也是它为什么一直不跑偏——代价是每步多一次截图。

## 2. 三个判据，层次分明（这是这题的核心思路）

| 层 | 用什么 | 成本 | 能力 | 局限 |
|---|---|---|---|---|
| ① 图像 | `panel_match`：块 vs 面板格的彩色 NCC（96×72，`matchTemplate` ±9px） | 0 步 | 直接答“这块放哪格”，实测**自家格 20/21** | 同类混淆块分不开 |
| ② 类别 | `identify`：YOLO11s-cls（15 类）+ 自训分类器投票 | 0 步 | 讲得清“这是狗”，可做配额校验 | 有 13/30 是两可的 |
| ③ 形状 | `white_edges`：孔/块的四边剖面（自校准中位数） | 0 步 | 白格唯一的身份 | 只对**已放置邻居**那一面有效 |

为什么 ① 放第一：**面板格和托盘里那块是同一张照片**。实测自家格相关 **0.662**，最强错误格 **0.380**；
换彩色+96×72+`matchTemplate` 后到 **0.67 / 0.91**。而类别只有 15 类、还要猜“哪只狗”，信息量少一个量级。
所以路线是：**图像定位置 → 类别补空位 → 形状管白格**（`plan = 图片计划；规则解只填空`）。

③ 的由来（这题最漂亮的一处）：白格的参考格是纯白瓦片，五个白块是同一张图，**没有任何图案可认**。
但站点把**空格需要的形状画了出来**——空格中心是灰度 23，边缘却有白色描边，(3,4) 那个孔是
**111×102、面积 4161** 的轮廓带（实心应约 9500，只占 37%）。于是：孔 = 棋盘上唯一的暗连通域，
它的四边剖面就是“该格需要的形状”；白块在托盘里也是暗底亮块，同一套判据。两侧同尺度，直接配对。

## 3. 落位验收：拿引擎自己的行为当裁判

不猜“我放下去了没有”，而是**按一下看它能不能被拿走**（`press_is_locked`）：

- 已吸附的块引擎拒绝拖动 → “拿不动”就是“锁上了”；
- 按 **3 个点**（中心 + 三个偏移），单点会误判：一版单点时循环报 17 格、页面只有 10 格；
- 每点 1.3 s，所以 3 次而不是 5 次（5 次每次验收多花 2.6 s，无可测收益）；
- 判据是 **亮度 + 纹理**：只比亮度时，暗块从 36 掉到 23（差值 13 < 旧阈值 25）会被判成“还在”；
- 测完必须**松手并把块放回原处**——早期版本松手前就返回，下一次抓取会拖走指针底下的东西。

失败就**拖回它自己原来的槽位**（不是“随便一个空位”）：托盘是按 129.92×98.6 的栅格排的，
一旦离开栅格，指纹就找不回它了，那块牌就等于丢了。

## 5. 三处真 bug（讲这段最能体现“工程”而不是“调参”）

**① 同一个问题有两把尺子。** 数托盘块数用 `is_empty`（中段均值<45 且 p99<20），而建库存用
`has_piece(…,20)`（均值≥20）。一块暗到均值<20 的块（黑色行李箱）被前者数成“有”，被后者跳过 →
它的格子整局都没有候选，最后停在 23/25。改：**一个判据**。

**② 计划被弱信号覆盖。** 规则求解器只要多覆盖一格，就会把整份图片计划替换掉（`if len(rule) > len(plan)`）；
规则解靠类别+切边，弱得多，于是出现“15–18 次拒绝”的局。改：`merged = dict(rule); merged.update(plan)`，
**图片优先、规则只补空位**。

**③ 同一对反复押注。** 排序是固定的函数，被拒的那块下一轮还排第一：
白格实测 `s12→cell(1,2)` 在第 24、31、37 步各被拒一次，10 次白格拒绝 = 20 步。改：
**未试过的形状优先**（一次被拒就不再排首位）。改完那一局从 47 步 → **25 步、0 拒绝**。

## 6. 现场演示（3 分钟）

```powershell
D:\python\python.exe stateless.py --dry --wait-deal 600     # 只看不做：打印计划，不动鼠标
D:\python\python.exe stateless.py --go  --wait-deal 900     # 真跑
```
（双击 `run.bat` / `dry.bat` 也行；**开局由人点**：部分 / 25 格 / 开始。）

讲的时候盯这几行日志：
1. `grid: 5x5 (tray holds 30 pieces…)` —— 先数托盘，不是 30 就退出码 3、不动鼠标；
2. `panel plan: 25/25 cell(s) matched by picture, best 0.89 / median 0.60` —— 图像匹配的把握；
3. `assignment: 25 cells (25 from the picture, 0 from the rule solver)` —— 谁主导；
4. `s31 (dog) -> cell(4,1)  [move 22]  LOCKED  20/25` —— 一进一出、验收过；
5. `board complete: 25/25 cells confirmed by the loop` —— 完成即停手（不再按压，避免点到结算弹窗）。

## 7. 大概率被问到

| 问题 | 答案要点 |
|---|---|
| 为什么不用 DOM / `window.__dev`？ | 考核要求“OpenCV+YOLO 识别屏幕 + 代码实现鼠标操作”；读内部数据等于作弊，且页面数据是考后证据 |
| 为什么按 3 次？ | 单点会误判（17 vs 10）；5 次每次多 2.6 s，无可测收益 |
| 96×72 怎么定的？ | 64×48 时自家格中位相关 0.60，96×72 是 0.67；再高（128×96、160×120）准确率都是 96%，没增益 |
| 为什么用最优指派而不是逐格取最大？ | 两块同时最像一格时，逐格取最大会把两块都送去同一格；指派全局最优，`tools/assign_test.py` 对暴力枚举 300/300 一致 |
| 白格凭什么一步定位？ | 空格边缘有白色描边 = 该格所需形状；孔是唯一暗连通域（邻块是亮照片，不会串味）；强制平边 47/47、真块 13/13 第一 |
| 步数怎么压到 25？ | 25 格 × 1 步；每格第一块就对。浪费只来自误判，每错一次 2 步 |
| 只能 5×5？ | 是。3×3/4×4 引擎会把棋盘缩小（531×399 vs 常量 560×425），标定全偏，实测 1/9；现在数托盘不是 28–32 直接退出码 3 |
| 鲁棒性靠什么？ | 几何标定 + 前台检查（非浏览器/非最大化 → 退出码 2、不动鼠标）+ 每步重截图，不依赖记忆坐标 |
| 失败会怎样？ | 拖回自己槽位；拒绝记录进 `logs/tried.json`；日志能看到“哪块被拒几次” |
| 已知限制？ | ① 初始重叠 / 初始居中未支持（块压在棋盘上，需要先剥洋葱）② 白底照片可能被读成白格（有降级修补）③ 显示器休眠会让 BitBlt 失败，跑之前别让它睡 |

## 8. 代码地图（被问“这块在哪”时用）

| 文件 | 职责 |
|---|---|
| `stateless.py` | 主循环：`Snap`（一次截图的几何）、`Pieces`（块的身份）、`white_candidates`（白格形状排序）、`press_is_locked`（验收）、`ring_order`（外圈→内圈） |
| `vision.py` | 版面几何、托盘栅格、空格/有块判据（`is_empty` / `has_piece`） |
| `identify.py` | YOLO11s-cls + 自训分类器投票、`is_blank` |
| `panel_match.py` | 图片相似度矩阵 + **最优一对一指派**（Kahn-Munkres，无 scipy 依赖） |
| `white_edges.py` | 四边剖面（块 / 孔 / 连续量），白格形状读数 |
| `jigsaw.py` + `assemble.py` | 切边规则求解器（图片计划的兜底）、合成自检 `--selftest` |
| `fingerprint.py` | 48×36 归一化模板，找块/核对原位 |
| `solve_live.py` | `Mouse`（真实事件）、DPI、前台检查 |
| `tools/` | 数据与模型（fetch/build/train）、以及四个验收工具：`tune_panel`（匹配器）、`assign_test`（指派）、`hole_test`（白格几何）、`tune_white`（白格真值） |
