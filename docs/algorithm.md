# 求解策略（含导师建议的四条硬规则）

## 一、为什么要"闭环拖拽"

pyautogui 的 `moveTo` + `mouseDown/Up` 是真实输入（SendInput），机制上没问题；
问题在**开环**：把光标移到格心就松手，落点误差由屏幕坐标换算一次性决定，实测偏差可达 40–60 px，
而引擎吸附容差只有 `max(0.14 × 格宽, 10 × pixelRatio)` ≈ 15 px，于是永远吸不上。

改为**闭环**：拖动过程中块是跟着光标一起渲染的，所以可以

1. 按下块 → 拖到格心附近（仍按住）；
2. 截屏，找到"被拖动的块"在画面上的实际位置（它是当前最上层、且位置随光标移动）；
3. 与目标格左上角求差 → 再把光标移动这个差（仍按住）；
4. 再截屏确认误差 < 5 px → 松手。

这才是人手的做法，也把精度从"一次性估算"提升到"逐帧收敛"。

## 二、失败必须回原位

任何一次放置如果没有让"进度 N/25" +1，就把它拖回**原始坐标**（记录 press 点即可）。
不允许把不匹配的块留在棋盘上——否则：

* 它会盖住空格，让"已填"判断失真（之前三次假成功就是这么来的）；
* 它会挡住下层块，导致库存采样漏类。

## 三、收尾必须清盘

跑完一轮后，棋盘上只允许存在**引擎确认吸附**的块（进度数字能证明的数量）。
其余任何内容一律拖回托盘，再进入下一轮——这样每一轮的"进度数字"与盘面严格一致。

## 四、按圈拼（与引擎规则天然一致）

站点 `PuzzleBoard.hasAnchor()` 规定：只有当格子在**最外圈**，或**相邻格已有落位块**时，
这一格才允许吸附。所以正确的放置顺序就是：

```
第 1 圈：外边框 16 格（顺时针扫一圈）
第 2 圈：内缩一圈的可锚定格
……
直到中心
```

实现上用 BFS 从外圈向内推进（`solve.placement_order()` 已实现），
每放好一格，它内侧的格子立刻获得锚点，于是"一圈一圈往里"自然完成。
顺时针顺序只影响扫描方向，不影响正确性，但便于人工核对日志。

## 五、当前唯一的阻塞点

`calib.py` 的决定性实验：同一块试遍 25 个格心（含 ±4 px 微调），进度数字一次未变
→ 说明不是格心坐标问题，而是**开环落点误差过大**或**抓取点抓空**。

下一步（按优先级）：

1. 闭环拖拽（本文件第一节），把落点误差压到 5 px 内；
2. 抓取点校验：按下后先截屏确认该点确实出现了"跟随光标的块"，否则换点；
3. 若闭环仍不吸附，再查站点 `ui/Controls.js` 的监听器是 `pointerdown` 还是 `mousedown`，
   以及是否存在 `pointerId` / `isTrusted` 校验。
